# 数系迁移使用说明

数系规则通过 `HSLayer.addRules(initialCreativeRules)` 加载。定理带有可检查的命令证明；动态数值定义和计算结果在首次使用时生成。

## 目录

- **皮亚诺算数**：公理、符号定义（含「1-10定义」）、定理。
- **数系**：自然数、整数、有理数、实数。自然数使用 `0`、`S` 和 `ℕ=ω`；整数用自然数对的等价类，有理数用整数对的等价类，实数用戴德金分割。

## 命令

`d` 是应用规则的命令；第二个 `d` 属于定义规则名称：

```text
d d3
d d37
d dZ-37
d dQ0.125
d dR37
d .0@N
d .3@N
d .2+3
d .2*3
d .+2@Z
d .+2+-3
d .-2*-3
```

前五条分别得到 `3=S(2)`、`37=S(36)`、`-37=Z((0,37))`、`0.125=Q((+125,+1000))`、`37r={x∈ℚ|x≤37q∧¬(x=37q)}`。随后得到自然数成员、加乘证明，以及 `+2∈ℤ`、`+2+-3=-1`、`-2*-3=+6`，均带 proof step，可通过 `genCmd` 导出并重放。

迁移包括 27 条皮亚诺定理、24 条集合桥接定理，以及 `.pn1`–`.pn5`、`.N@+`、`.N@<=`、`.<=Rel`、`.<=Order`。所有派生规则保留实际证明；`.pn1`–`.pn5` 还单独在不加载皮亚诺公理的 ZFC 环境中验证。

自然数动态定义须已加载 `apn1`；整数、有理数、实数动态定义分别须已加载 `dZ`、`dQ`、`dR`。其他数系的规则不能代替此前置条件。`d0` 是 `0={}` 的集合定义；零属于自然数使用 `apn1` 或 `.0@N`。

`1`、`+1`、`1q`、`1r` 是不同数系的字面量；`-1`、`-1q` 保留符号。除法 `/` 与乘法同级、从左结合，高于加减。`d a7 S(0)` 可直接使用函数项；关系式 `x=y` 不能作为项参数。紧跟条件编号的带符号参数用括号隔开，例如 `d <a4 1 (-2)`；命令导出也会自动保护这类参数。

## 预算与存档

自然数证明采用 **1000-successor** 预算：成员证明的数值、加乘输入及结果均不得超过 1000，超出会明确报错。此预算限制证明展开，动态字面量定义本身仍用 BigInt 精确处理。

整数成员及加、减、乘证明同样限制自然数表示中的输入和中间坐标不超过 1000。有理数、实数本次迁移定义与字面量，不额外添加旧版没有的自动计算证明。

规则表使用 `Serde.serializeRulelist()` / `deserializeRulelist()` 保存和恢复目录、顺序及证明。静态 `a`/`d` 公理保存为名称占位符，恢复时采用当前初始库定义。动态规则缓存不自动进入规则目录；推理表命令重放时重新生成所需规则。集成回归同时检查完整初始库、规则表往返与命令重放。

## 保留与更正

实数倒数采用已批准的更正：`dR/1` 的正数倒数下分割包含 `z≤0q`，正数部分使用 `m∈ℚ＼x`、`¬m≤0q`，且 `z≤1q/m∧¬z=1q/m`，排除分割端点；`dR/2` 保留分母非零条件 `¬y=0r`。旧存档中的静态定义占位符会采用此版本。

`dPrime` 保留原定义及名称，包括原有边界语义；本次迁移不额外加入 `n>1` 条件。

`dQ<=` 按已批准的更正，将分母乘积非负条件中的自然数零 `0` 改为整数零 `+0`，与整数分母保持同一数系。

## 运行回归

先编译本仓库 TypeScript 到 `js/`，再运行：

```text
node test/test-number-integration.mjs
node test/test-number-literals.mjs
node test/test-peano-proofs.mjs
node test/test-number-set-proofs.mjs
node test/test-natural-set-proofs.mjs
node test/test-set-substitution.mjs
```

测试只导入 `../js/` 编译产物，遍历当前完整静态库，不固定规则数量；任何规则的 `error` 或证明缺失都会使测试失败。整数回归覆盖 212 个案例，并逐一导出命令、在独立环境中重放。

全量执行 `test/test-*.mjs`：29 个脚本中 24 个通过；`test-combine`、`test-cvexpand`、`test-folder`、`test-folder2`、`test-gtrule` 在迁移前的干净提交中也失败，本次没有增加失败脚本。项目尚无 `package.json` 测试入口，故直接逐个运行这些脚本。
