# 地图作者工具

打开 `tools/map-editor/`。项目 JSON 用于继续编辑；发布的世界 JSON 用于游戏导入。

- **批量编辑**：选区可一次修改格子类型、奖励和脚本，也可填写高级 JSON 补丁。删除前先查看引用影响；选区或项目变化后须重新预览。一次批量操作对应一次撤销。
- **搜索替换**：可搜索文字、稳定 ID、属性及脚本。先预览匹配和替换结果，再应用。全图问题面板可定位格式、引用、依赖环及拓扑提示；它不判定任意证明关卡是否可解。
- **结构化表单**：门条件、付费、奖励、拆门目标，以及银行和迁移计划均可填写表单。格子表单先“写入表单”，再用原有 Apply 提交；未提交内容会阻止直接切换。高级 JSON 仍可使用。
- **作者调试**：从编辑器试玩进入独立调试存档，查看事件轨迹、失败条件、钥匙、flag、计数和 once 状态，并捕获/恢复完整游戏快照。不会写入普通游戏进度。
- **内容库**：先配置世界，再填写检查过的定理、显式定义、多语言笔记和成就。条目加入列表后还须“应用内容库”。定理证明使用游戏证明命令，应用时实际重放；循环证明及错误结论会被拒绝。
- **发布与恢复**：发布信息可声明作者、简介、引擎版本和依赖 revision。世界包包含当前世界及本地已安装的依赖，可附带原生 `.dt` 存档。导入包先安装世界，再明确启用/进入对应世界并恢复存档。迁移差异面板比较旧版与当前版本的格子、目标及 remap/reset。

## 地图自有规则

在内容库中添加已检查定理，例如：

```json
{"id":"qIdentity","statement":"⊢$1→$1","proof":"d .i $1"}
```

通过格子脚本领取：

```text
unlock rule qIdentity
```

领取时仍检查已获得的前置公理。声明定理不会自动授予尚未获得的公理。多个启用的世界不能占用相同规则名或定义符号；更改逻辑内容须提升 revision 并配置迁移。

定义使用新符号和显式项参数，禁止递归、自由参数及替换指令。例如：

```json
{"id":"qFresh","kind":"function","symbol":"freshFn","parameters":["$x"],"body":"$x"}
```

常量以零参函数 `freshc()` 表示；谓词的定义体须为完整公式。定义也须通过 `unlock rule` 领取。自定义笔记和成就 ID 在运行时按世界命名空间隔离，显示为纯文本。

类型论旧定义谜题与战术的内核迁移仍保持原范围；本次作者工具没有补写这些检查器。
