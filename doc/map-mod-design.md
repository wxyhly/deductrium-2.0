# 地图模块后续设计约束

本文件记录 2026-11-07 作者补充的方向，区分已完成的编辑器原型与后续 mod 运行时。

## 当前可用

- 地图编辑、模块 JSON 导入导出、六向旋转与挂载；位置变换直接使用游戏的 `{6,4}` 双曲铺砌。
- 模块实例隔离名称、脚本钥匙、标记和计数器，挂载前检查实际砖块位置冲突。
- 独立空图或现有地图编辑，使用正式游戏进行隔离试玩。
- 试玩存档与正式生存存档分开；当前按地图内容区分试玩存档，地图内容改变后开始新的试玩进度。

当前的挂载碰撞检查不等同于半平面限制；当前试玩存档隔离也不等同于 mod 更新后的进度迁移。项目和模块 JSON 格式仍属于开发格式。

## 货币与银行

推理层与类型层分别记账，不共用余额。银行通过明确的兑换操作连接两个余额，并收取手续费。

兑换配置需要包括源币种、目标币种、汇率、手续费、最小兑换额和舍入方式。一次兑换必须同时检查并提交两边余额；存档必须保留独立账本，不能把旧的单一余额直接复制成两份。汇率、手续费数值及旧存档归属由玩法设计确定。

本次脚本 `give/take money` 仍操作现有推理素；没有提前引入类型货币或银行。

## mod 入口与世界模式

mod 采用 JSON 数据文件，声明稳定的模块 ID、版本、入口砖块及朝向。建议明确区分：

- **扩展主世界**：保留主世界，通过指定入口连接；实例 ID 用于隔离局部砖块和进度。
- **独立世界**：从空地图开始，指定出生点和独立存档，不继承主世界的隐式奖励或货币。

发布用 mod 运行时应从 JSON 加载数据；不执行导入文件中的 JavaScript。现有项目导出保存编辑信息，地图源码导出用于当前游戏的静态地图，二者不应混作发布格式。

## 半平面编辑范围

由作者在双曲空间中指定一条测地线并选择允许的一侧；入口位于边界或连接位置。编辑、导入、旋转和挂载都应检查同一个范围约束，不能只在画布上遮住另一侧。

需要明确边界砖块按中心点还是整个多边形归属，以及入口如何跨越边界。建议发布校验采用完整砖块归属，并单独声明入口连接，以避免跨界重叠。具体边界操作和判定应在实现前用真实铺砌验证。

## 地图更新与进度兼容

发布后的模块、实例和砖块都需要稳定 ID，位置或显示名称变化不改变身份。存档按世界 ID、实例 ID、砖块 ID 记录奖励领取、开门、钥匙和脚本执行状态；不把坐标或当前文本当作唯一身份。

地图版本与存档版本分别管理。更新至少区分保留砖块、改名迁移、删除砖块、新增砖块和谜题条件变化；脚本奖励不能因版本更新被重复发放。目标或条件发生变化时需要显式的进度迁移决策，不能仅凭旧的“门已开”状态通过新题。

加载时先验证整份迁移计划，成功后一次提交；失败保留原存档并给出可导出的备份。更新前后世界选择和独立世界隔离也要进入兼容测试。
