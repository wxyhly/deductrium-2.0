# 地图文案工作台

从仓库根目录启动任意静态 HTTP 服务，例如 `python -m http.server 8766 --bind 127.0.0.1`，打开 `http://127.0.0.1:8766/tools/map-text-editor/index.html`。不需要安装前端依赖；不能直接用 `file://` 打开。

左侧按文案、命名锚点、坐标或源码行号搜索，点列表定位；中间地图支持拖动和单击选格。默认显示推理层与公共区域的提示格，切换“所有文字格”可编辑奖励或题目文字。区域筛选根据现有地图的 `:type` 分支至“序数附加”分段，不是对文案内容的自动分类。

右侧直接编辑中文、英文。回车对应地图换行，`[n]`、`[zh]` 等手动输入内容按字面文字保存。添加语言时，无语言标记的原文归入中文；原有其他语言会保留。上一轮的66条措辞建议只在原文精确匹配时显示，必须点击才能采用，不会批量替换地图。

修改自动暂存于浏览器专用存储，不接触游戏存档。刷新可继续；浏览器拒绝暂存时会明确提示。使用“导出草稿”保存原地图及逐格修改，之后通过“导入 map.ts / 草稿”恢复；切换服务器端口或浏览器时请使用这个草稿文件。

旧草稿恢复失败时保留原记录，并提供“导出未恢复草稿”；本次编辑请另存草稿文件。地图文字格式无法表示反斜杠紧接换行、或多个语言字段均以反斜杠结尾的情况：编辑器会保留草稿并阻止有损的 `map.ts` 导出，修正文案后恢复导出。

“导出 map.ts”下载完整源码，只替换已编辑行的文字部分，保留坐标、名称、元数据、注释、未修改行及原有换行。它不会写回服务器上的文件。人工审阅下载文件后再替换 `src/hy/map.ts`，并按项目通常方式编译。仅导入草稿会核对完整原地图；不匹配或损坏的草稿会被拒绝，当前内容不会被覆盖。

第二个页签列出40项推理层变化。对应的 Markdown 表在 `doc/reasoning-2.0-changes.md`，数据在本目录 `changes.json`。编辑器自身不依赖游戏中的奖励或证明进度。

验证：`node test/test-map-text-editor.mjs`。浏览器回归：安装 Playwright 后执行 `node test/browser/map-text-editor.mjs`；也可通过 `PLAYWRIGHT_MODULE` 指向本机已有的 Playwright 模块。浏览器测试自建临时服务，使用本机 Chrome，不操作桌面。
